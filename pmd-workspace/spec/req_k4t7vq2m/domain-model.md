# 领域术语 — req_k4t7vq2m（优化司机接单流程）

> 状态标注：`[代码确认]` = 已由 H5_前端 远程证据支撑；`[待确认]` = 待用户/后续证据对齐。

| 术语 | 定义（实现无关） | 状态 |
|---|---|---|
| 司机（Driver） | 承接运输任务并在 H5（内嵌原生 App）完成接单操作的终端角色 | [代码确认]（EV-11/12，dsBridge 存在） |
| 接单（Order Acceptance） | 司机对可承接订单执行确认承接的动作及前后交互 | [代码确认] |
| 链路 A · 货源大厅接单 | 司机主动找货：列表→详情→确认页，按 `freightType` 分抢单/报价/认领/一口价 | [代码确认]（EV-01~05） |
| 链路 B · 任务详情接单 | 平台派单场景：手动接单 + 自动接单倒计时（服务端实际接单） | [代码确认]（EV-06/07） |
| freightType | 货源交易类型：0 抢单 / 1 报价 / 2 认领 / 3 一口价 | [代码确认]（EV-01/08） |
| driverConfirmStatus | 司机确认状态：'' 未确认 / '20' 已确认接单 / '30' 拒绝 | [代码确认]（EV-08） |
| 押金支付 | 一口价/抢单成功后的保证金支付环节，支付状态由 `getPayStatus` 查询 | [代码确认]（EV-05/13） |
| 找货记录（SupplyRecord） | 接单/报价成功后的结果页，展示抢单与押金/退款状态 | [代码确认]（EV-13） |
| 自动接单（Auto Accept） | 派单场景下倒计时归零由服务端自动确认接单，前端仅展示与刷新 | [代码确认]（EV-07） |

## _Avoid_

- 不把「接单」与「派单」「抢单」「改派」混用：抢单是链路 A 的 `freightType=0` 子类型；派单是链路 B 的前提。
- 不说「前端自动接单」：链路 B 的接单动作发生在服务端，前端只有倒计时展示（EV-07）。
- 不用「当前标签页」等本地词汇描述业务对象；流程对象以远程代码库实际模块命名为准。
- 不把 `driverTaskStatus` 注释值（10/20/30/40）当运行语义，运行值为 60/70/50（EV-08 注释过期）。
