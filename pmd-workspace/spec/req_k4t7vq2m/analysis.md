# 需求分析与研发交付：req_k4t7vq2m - 司机接单流程优化

## 1. 需求理解与范围

- **目标**：优化司机接单流程。P1（纯前端）将接单操作从现状 3 跳（列表→详情→确认页）降为 ≤2 步（统一接单确认抽屉）；P2（后端配合）将货源超时/下架状态变化的前端感知时限提升到 ≤10 秒。
- **用户**：司机（H5 内嵌原生 App 的移动端角色）。
- **边界**：H5_前端 为主改造方；后端为配合方（P2 状态感知接口）；不动原生 App（dsBridge 推送留二期）。
- **非目标**：后端派单/撮合策略、押金收银台自身流程、原生推送通道改造、报价定价策略。
- **术语与不变量**：链路 A（货源大厅：freightType 0 抢单/1 报价/2 认领/3 一口价）、链路 B（任务详情派单：手动接单 + 服务端自动接单倒计时）、`driverConfirmStatus`（'20' 已接 / '30' 拒绝）语义保持不变；押金支付合规链路不变；接单提交必须幂等（连点仅一次请求）。术语明细见 `domain-model.md`（均已代码确认）。
- **待确认项**（5 项，贯穿全文以 `[待确认]` 标注）：
  1. 4 类 freightType（尤其报价类需价格输入）是否全部开放列表快捷入口。
  2. iOS 内置组件 `showView='takeOrder'` 路径的迁移方式。
  3. 迁移后 TakeOrder/Tuotation 旧确认页下线还是长期保留深链。
  4. P2 后端状态感知接口的形态（轮询/推送）与排期。
  5. 埋点体系接入方式与接单耗时基线数据来源。
