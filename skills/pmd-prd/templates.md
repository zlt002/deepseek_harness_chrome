# 单 PRD 模板入口（仅导航）

需要生成、冻结或校验正式正文时，先完整读取同目录 [`references/templates.md`](references/templates.md) 的全部内容。该文件包含唯一 PRD 的完整模板和填写规则；本文件不提供可替代的摘要模板。

阶段 5 将完整 PRD 正文原样落到同一过程目录，规范文件名为 `{需求标识}_{主题}_PRD.md`，再运行 `scripts/validate-deliverables.mjs --prd <prd-frozen-path>`。只有校验通过，才允许以一项 PRD 进入后续写入。

缺失事实使用 `[待确认]` 并说明影响；不适用使用“不适用（原因）”。生成正文必须保留权威模板的全部章节、顺序和关键表头。第四章以“改动点 → 具体子项”两层展开；子项标题下可用一行正文说明适用页面，每个子项都有“需求点｜类型｜原有实现｜目标修改点”研发改动说明表。目标修改点以研发执行视角、按实际复杂度把代码库完整相对路径、接口和稳定位置绑定到对应需求行，再说明具体逻辑变化、关键状态或联动和可观察效果；表后的“实现约束与验收规则”只写实施完成后必须满足的业务与系统规则。第八章必须包含基于查询证据的“关联改动与风险”、回归范围、独立的“异常场景关注点”和五类“验收清单”。最终标题和正文不得出现 `[必填]`、`[选填]` 或 `[建议填写]` 字段标签。
