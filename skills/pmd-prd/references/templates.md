# PRD 产品需求文档模板与填写规则

这是唯一 PRD 模板源。生成和检查 PRD 时，先遵循以下写作要求，再按模板内注释填写。

## 写作要求

- 使用最少必要信息：功能性需求是主体，同一信息只写一次；描述/痛点最多简要概括一两句；目标/价值只有用户确认时才具体写；流程优先用“入口→关键操作→结果”一句话，只有确有必要才画图且只保留主干。模板章节和小节全部保留，确认不涉及时写“无”或“不涉及”。
- 先写清需求点，再写研发定位。主体写清用户要什么、现在怎样、要改成怎样、如何使用和如何验收。
- 证据边界：用户当前对话直接提供或确认的内容均视为用户确认。只有第四章功能改动点可综合用户确认、正式资料明确规定和代码查询；代码只证明现状、关联影响和研发定位，目标改动仍须用户确认或正式资料明确规定。
- 其他章节和字段不从代码库、资料或模型推断直接填充。必填内容必须向用户确认后填写；资料只能作为候选依据，不能代替确认。研发定位必须经代码查询确认，可靠位置不可得时不能生成最终 PRD。代码变量名和组件名不进入 PRD；类名或函数名仅在文件定位仍无法消除歧义时补充。
- 截图只能证明当时看到的页面，不能证明完整代码或全部影响。用户决定业务选择，不决定类名、接口或数据库实现。
- 模板标为必填的项必须取得真实信息并填写；信息不足时先向用户澄清，不能用“无”代替。只有确认不涉及的项才写“无”或“不涉及”；需求基本信息只有选填字段未知时可以留空。
- 最终 PRD 删除填写注释，不保留占位符、空章节、空表或无依据数字；确认不涉及的章节、小节或表格位置用“无”或“不涉及”表示。
- 澄清交互中，用户只需看到结论、需要决定的问题和推荐方案，不展示内部文件名、编号或工具参数；最终 PRD 第四章可在必要时展示页面路由、接口和仓库相对文件定位。

除第八章补充验收清单外，章节、字段和顺序均沿用《PRD 产品需求文档模板（2026/04/10）》。
