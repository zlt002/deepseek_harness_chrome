# PRD 产品需求文档模板与填写规则

这是唯一 PRD 模板源。生成和检查 PRD 时，先遵循以下写作要求，再按模板内注释填写。

## 写作要求

- 使用最少必要信息：功能性需求是主体，同一信息只写一次；描述/痛点最多简要概括一两句；目标/价值只有用户已确认且输入资料明确有依据时才具体写；流程优先用“入口→关键操作→结果”一句话，只有确有必要才画图且只保留主干。模板章节和小节全部保留，确认不涉及时写“无”或“不涉及”。
- 先写清需求点，再写代码位置。主体写清用户要什么、现在怎样、要改成怎样、如何使用和如何验收。
- 证据边界：只有第四章功能改动点可综合用户输入、用户提供/选定资料和代码查询；代码只证明现状、关联影响和研发定位，目标改动仍须用户确认或正式资料明确规定。
- 其他章节和字段不从代码库或模型推断直接填充。必填内容必须向用户确认后填写；用户提供/选定资料只能作为候选依据，不能代替确认。代码字段、变量、类名和组件名只写在第四章研发定位。
- 截图只能证明当时看到的页面，不能证明完整代码或全部影响。用户决定业务选择，不决定类名、接口或数据库实现。
- 模板标为必填的项必须取得真实信息并填写；信息不足时先向用户澄清，不能用“无”代替。只有确认不涉及的项才写“无”或“不涉及”；需求基本信息只有选填字段未知时可以留空。
- 最终 PRD 删除填写注释，不保留占位符、空章节、空表或无依据数字；确认不涉及的章节、小节或表格位置用“无”或“不涉及”表示。
- 用户只需看到结论、需要决定的问题和推荐方案，不展示内部文件名、编号或工具参数。

除第八章新增的五类验收清单外，章节、字段和顺序均沿用《PRD 产品需求文档模板（2026/04/10）》。
